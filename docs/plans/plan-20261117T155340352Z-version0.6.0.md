# PLAN — uso del provider en la barra de estado

Plan aprobado por el usuario: **«sí, implementa»**, 2026-11-17. Implementación en curso. Solicitud y
captura del usuario: 2026-11-17. Reproducir Codex Usage de ganymede404, adaptado
a la facturación del provider activo de cada workspace.

La barra sola sería patch según la política del proyecto. Este plan propone
también ampliar las lecturas de cuotas de Z.AI y MiMo: versión conjunta propuesta
**0.6.0**, por ampliación sustancial de providers existentes. No añade providers.
Base revisada: main `e15ca06`, manifest/instalación 0.5.5. Último tag/release
encontrado: 0.5.4, base del marcador generado. Revalidar versiones al implementar.
La publicación pendiente de 0.5.5 no forma parte de este estudio.

## Clasificación de los diez providers

Revisión de código y fuentes oficiales: **2026-11-17**. Facturación real y
disponibilidad de una API con la clave guardada son cuestiones diferentes.

| Provider / modalidad integrada | Tipo de recurso | Lectura viable y situación actual |
| --- | --- | --- |
| ChatGPT Plan | Cuotas por ventanas; algunas cuentas tienen créditos adicionales | App-server oficial. Renderizar ventanas reportadas, no deducirlas del plan. Plus puede tener 5h y semana; Pro 100/200/500 no tiene actualmente límite 5h. El normalizador actual solo conserva 300/10080 minutos: hay que generalizarlo. |
| DeepSeek | Saldo monetario | Ya existe `/user/balance`. Contrato USD/CNY; integración actual selecciona USD. No convertir ni sumar monedas. |
| OpenRouter | Créditos monetarios de cuenta; también límites por clave | Ya existe `/credits`: total menos uso. Puede devolver 403 por permisos. Un límite de clave no es saldo de cuenta y no lo sustituye. |
| OpenAI API | Consumo facturado, prepago y modalidades de organización | No hay contrato de saldo restante establecido con la clave de inferencia actual. Usage/Costs/administración requieren otros permisos; no confundir gasto, RPM/TPM o ChatGPT Plan con saldo. |
| Z.AI, GLM Coding Plan personal | Ventanas 5h/semanales; créditos en planes nuevos, solicitudes en legacy | Hoy `usage:false`. El plugin oficial personal consulta `/api/monitor/usage/quota/limit`. Añadir adaptador de solo lectura; no copiar su antigua suposición de una sola ventana 5h ni mezclar cuota MCP mensual con cuota del modelo. |
| Moonshot AI / Kimi API | Saldo monetario | Ya existe `/users/me/balance`: USD global, CNY China. No es la cuota de una suscripción del chat web. |
| Qwen Token Plan | Créditos de suscripción por ciclo y posibles packs | Estadísticas oficiales requieren AccessKey/RAM y firma ACS3, rechazan Bearer de la clave Token Plan. No accesible con la configuración actual. |
| Qwen PAYG | Consumo facturado/saldo de cuenta | No hay contrato establecido de saldo restante con la clave de inferencia integrada. Mantener separado de Token Plan. |
| xAI / Grok | Créditos prepagados o factura mensual | Gestión/facturación requiere Management Key distinta. No accesible con la clave actual; un límite de gasto no equivale a saldo. |
| MiniMax M Plan | Cuotas por ventanas y posibles packs de créditos | Ya se consulta `/token_plan/remains`. Reutilizar porcentajes explícitos/reinicios; distinguir ilimitado, ausente y cero. Conservar semántica documentada del boost; no adivinar contadores legacy ambiguos. |
| MiniMax PAYG | Saldo monetario/consumo | No mostrar una cifra sin contrato con moneda explícita. No usar saldo PAYG como cuota M Plan ni intercambiar tipos de clave. |
| MiMo PAYG | Saldo monetario | Hoy `usage:false`, pero ya está documentado `/v1/platform/balance` con clave normal. Añadir adaptador: moneda explícita, saldo gastable y cantidades congeladas según contrato. |
| MiMo Token Plan | Créditos propios del paquete, no dólares | Documentado `/v1/platform/token_plan`, clave dedicada `tp-`. Mostrar Credits restantes y ciclo/expiración en tooltip, sin asumir semana o renovación automática. |

**Viabilidad:** reutilizar las cuatro fuentes API actuales y ChatGPT; ampliar
Z.AI personal y MiMo con fuentes oficiales. OpenAI API, Qwen y xAI no pueden
prometer una cifra con las credenciales actuales. Propuesta para ellos:
`Provider —` normal, tooltip con motivo. Lo mismo ante permisos insuficientes;
nunca inventar cero o porcentaje. No se han usado claves reales en este estudio.

## Referencia comprobada

Inspeccionada la extensión instalada **ganymede404.vscode-codex-usage 0.2.4**:
manifest, `out/statusBar.js`, `out/format.js`, licencia MIT. No modificada.
Arnés aislado con VS Code simulado, sin autenticación, red o conversaciones:

```text
[OpenAI] Codex 5h 97% · 41m | Week 33% · 3d 23h
[OpenAI] Codex Week 9% · 1d 0h
[OpenAI] Codex Month 20% · 1h 0m
```

Los tres formatos son resultados verificados de la referencia. Porcentajes
**restantes**. Ejemplos propuestos para otros recursos, sin cifras de cuenta real:
`[DeepSeek] DeepSeek USD 2.14` y `[MiMo] MiMo 8,500,000 Credits`.
La barra conserva el formato temporal compacto de Codex Usage; las tarjetas
mantienen sus reglas de cuenta atrás. Tooltip con fechas exactas y hora local.

VS Code no permite un SVG arbitrario en `StatusBarItem.text`: conservar los SVG
como fuente y empaquetar WOFF monocromático en `contributes.icons`, como hace
Codex Usage. Nada se descarga o convierte en el equipo del usuario; no hay
dependencia de esa extensión. Conservar atribuciones de los logos.

## B01 — Contrato de métricas y adaptadores

**Objetivo:** tarjeta y barra reciben el mismo dato normalizado, con provider,
contexto, `capturedAt`, disponibilidad y unidad. Modalidades `windows`, `money`,
`credits`, `unavailable`; no fusionar pools, modelos, divisas o cuentas.

- Ventanas con identificador, duración conocida, restante y reinicio propios.
  No asumir primary=5h/secondary=semana. Generalizar `codex-account.normalize`,
  migrando su renderer sin perder campos actuales, plan ni banked resets.
  Usar bucket Codex; nunca cuotas de otra funcionalidad como cuota de Codex.
- Reutilizar DeepSeek/OpenRouter/Kimi/MiniMax. Añadir Z.AI personal y MiMo con
  almacén/broker existentes, hosts oficiales y autenticación específica. Z.AI
  no necesariamente usa el mismo encabezado Bearer que los otros servicios.
- Validar fixtures del contrato vigente Z.AI antes de habilitar el adaptador:
  su ejemplo oficial antiguo no establece el esquema semanal de planes nuevos.
  Si una ventana no se identifica con certeza, disponibilidad parcial explícita.
- MiMo dinero: moneda y valor gastable, contemplando congelados. Token Plan:
  Credits propios y ciclo; no convertir a USD ni asumir renovación.
- 401/403/429, respuesta parcial/desconocida/no finita no son cero. Un 403 de
  facturación no revoca la configuración válida de inferencia. Sin nuevas claves
  administrativas, scraping de dashboards o APIs privadas de facturación.

**Aceptación:** semana única preservada; otras duraciones no se pierden; cifra,
unidad y ámbito correctos. Ninguna lectura cambia provider/modelo/configuración
global o autenticación. No realizar inferencias para consultar uso.

## B02 — Servicio compartido fuera del sidebar

**Objetivo:** barra operativa sin abrir el panel, sin duplicar consultas.

- Extraer métricas de la dependencia de `this.view`. Demanda = provider activo
  verificado de la barra, o tarjeta visible en panel abierto. Provider desmarcado
  no hace peticiones; el activo conserva su visibilidad obligatoria.
- Panel cerrado: solo métricas del activo, al iniciar y cada 60s. No descargar
  todos los catálogos ni revalidar todas las claves cada minuto. Compartir lectura
  con tarjetas abiertas; preservar sync silencioso y sync explícito existentes.
- Un reloj local para cuentas atrás, sin red. Dedupe, cancelación y backoff
  acotado. No solapar peticiones ni ciclos durante una operación de credenciales.
- Descartar respuestas anteriores al cambiar provider, endpoint, credencial,
  cuenta, workspace o nonce. Caché vinculada a ese contexto, sin secretos.
- Solo atribuir métricas al provider confirmado en esa ventana. Sin confirmación:
  `Codex Switch —`, neutral, tooltip explicativo. No inferir desde TOML global o
  preferencia guardada; no afirmar provider del chat histórico abierto.
- Durante refresco, conservar lectura anterior. Si falla al terminar:
  `Provider —` con motivo y última lectura fechada en tooltip. No presentarla
  como fresca. Cuenta atrás a cero no repone cuota al 100%: refresco acotado.
- Un elemento/servicio por ventana. Liberar timers/requests al desactivar,
  desinstalar/cerrar. Sin recargas automáticas de arranque o cambios del launcher.

**Aceptación:** dato común tarjeta/barra; funciona con panel cerrado; ningún
provider inactivo adquiere demanda por la barra; cambios y respuestas tardías
local/SSH no mezclan cifras ni provider.

## B03 — Barra nativa e iconos

**Objetivo:** un elemento por ventana, a la derecha como en la captura.

- Icono propio y `Codex` para ChatGPT, o nombre breve del provider; segmentos
  `5h 97% · 41m | Week 33% · 3d 23h`. Todas las ventanas aplicables disponibles,
  ordenadas por duración; desconocida no se etiqueta como 5h.
- Saldo: nombre, cantidad y unidad real. No redondear saldo positivo pequeño a
  falso agotamiento. Precisión completa en tooltip, sin conversiones monetarias.
- Fuente WOFF empaquetada desde siluetas SVG de los diez providers; conservar
  fuente SVG/atribuciones. Revisar huecos, gradientes aplanados y legibilidad pequeña.
- Tooltip: provider/plan/modalidad, reinicios locales, ámbito/unidad, última
  actualización y motivo de indisponibilidad. Sin email, claves o respuestas crudas.
- Clic abre Codex Switch con su comando existente. Identificador estable,
  nombre/etiqueta accesibles y ocultación desde el menú nativo de la barra.
- Codex Usage puede seguir instalado: no modificarlo, ocultarlo o desinstalarlo.
  No depender de su WOFF o archivos instalados. Reimplementación propia del formato.

**Aceptación:** formato fiel a referencia 0.2.4, glifos y tema legibles, fuentes
locales empaquetadas; sin rutas personales ni generación durante instalación.

## B04 — Color y coherencia de tarjetas

Aplicar los límites sobre cifras originales, sin redondear:

| Métrica | Rojo | Amarillo | Normal |
| --- | --- | --- | --- |
| Ventanas porcentuales | Alguna restante 0–10%, inclusive | Ninguna roja y alguna >10% y <=25% | Todas >25%; ausente no es 0 |
| Dinero/credits, límite >0 | Restante <=0 | Restante >0 y menor que límite | Restante >=límite |
| Dinero/credits, límite 0 | Nunca por agotamiento | Nunca por saldo bajo | Incluso saldo cero/negativo |

- La peor ventana determina el nivel, no solo la primera. Una ventana agotada
  no prueba bloqueo total si existe una bolsa adicional; distinguirlo en tooltip.
- Propuesta visual fiel a Codex Usage: `statusBarItem.errorBackground` y
  `statusBarItem.warningBackground`, foreground accesible del tema; normal sin
  colores forzados. Datos ausentes/viejos no activan advertencia de saldo.
- Centralizar niveles: el umbral monetario/de Credits es el mismo Balance alert
  que la tarjeta. Baseline separado cuando cambia modalidad/unidad.
- Porcentajes fijos 10/25 también para MiniMax/Z.AI: petición nueva que amplía
  la anterior regla exclusiva de ChatGPT. Mantener umbrales de dinero y las
  notificaciones optativas: no habilitarlas por defecto ni duplicarlas desde barra.
- Conservar silencio inicial, cruces descendentes y recuperación/rearme de
  alertas existentes. Cambiar límite no genera consultas o avisos espurios.

**Aceptación:** tarjeta y barra coinciden, prioridad rojo>amarillo y umbral0
neutral aun con saldo0. No cambiar la regla anterior de las barras ChatGPT.

## B05 — Pruebas y puertas de entrega

No prometer ausencia universal de errores: exigir estas verificaciones.

1. **Contratos:** Plus dos ventanas, Pro semanal única, mensual/diaria/desconocida,
   campos parciales, ilimitado/cero, otro bucket, sin reinicio, NaN/infinito.
   MiniMax legacy/boost/porcentaje explícito; Z.AI personal/legacy/esquema
   desconocido; MiMo dinero/Token Plan/congelados/moneda/expiración.
2. **Color:** 0/10/10.01/25/25.01/100%, cualquiera de las ventanas crítica;
   saldo negativo/0/bajo/igual/superior al límite, límite0/inválido/cambiado.
   Verificar dato original frente al redondeado y recuperar color normal.
3. **Tiempo/formato:** texto exacto de referencia, semana única, 0m, minutos,
   horas/días, reinicio, DST, reloj cambiado, sin `NaN` o `undefined`.
4. **Servicio:** panel nunca abierto, abrir/cerrar repetidamente, sync simultáneo,
   cancelaciones, respuestas invertidas y cambios de provider/clave/cuenta/endpoint.
   Reloj sin red; lectura compartida sin duplicados; providers ocultos sin llamadas.
5. **Errores:** 401/403/429/500, timeout, SSH desconectado y recuperación. Permiso
   de saldo denegado conserva configuración; desconocido no se pinta como agotado.
6. **VSIX y Codex reales:** instalación limpia; dos workspaces con providers
   distintos, reabrir y reiniciar host forzando Codex antes de Switch; carpeta y
   ventana vacía; native model picker. Sin bucles, recargas o pérdida de secretos.
   Repetir en local y SSH picasso, con barra y tarjeta del mismo provider.
7. **Ciclo de vida:** deshabilitar/desinstalar con Codex activo: retirar barra,
   timers y listeners, conservar Codex normal, claves y selecciones. No alterar
   la instalación de Codex Usage ni datos de autenticación durante QA.
8. **Visual/accesibilidad:** barra real derecha, temas claro/oscuro/alto contraste,
   escalado, logos y colores legibles, ancho estrecho, tooltip y lectores de pantalla.
   Un mock no demuestra revisión visual. Si inspección real requiere interrumpir
   una conexión activa, coordinar recarga/revisión; Computer Use solo si aporta y
   está autorizado, con limpieza de captura obligatoria.
9. **Entrega:** suite apropiada y matriz Windows/macOS/Linux x64/ARM64; pruebas y
   build paralelos si independientes. Cancelar solo build propio ante fallo.
   Verificar fuente/VSIX/instalado, WOFF/atribuciones incluidas. Instalar exacto en
   perfil actual y remoto, verificar versión cargada y declarar recargas pendientes.
   Todo se entrega/crea desde VSIX, sin depender del PC del desarrollador.

Antecedentes de claves reales comprobadas en este entorno: ChatGPT, DeepSeek,
OpenRouter. Los otros siete providers usarán fixtures oficiales; si no hay claves
disponibles, su verificación con cuenta real quedará explícitamente pendiente.
No consumir créditos de inferencia para validar una barra de estado.
