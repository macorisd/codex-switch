# PLAN - version 0.2.0 (minor)

## Objetivo y alcance

Ampliar las opciones de proveedores con API key para mostrar el catálogo de
modelos en un desplegable contraído y añadir una sección Usage con saldo,
sincronización periódica y alertas configurables. DeepSeek es el primer
proveedor que usa esta capacidad.

El dashboard histórico queda excluido de 0.2.0 hasta que DeepSeek publique una
API oficial de usage. La API de balance documentada sólo entrega el saldo actual.

## Bloques de cambios

<!-- md-block {"id":"B01","dependsOn":[]} -->
## B01 - Model catalog disclosure

Objetivo y resultado observable: el catálogo de modelos de proveedores con API
key queda contraído por defecto y se puede desplegar.

Alcance y comportamiento:
- El desplegable contraído no ocupa espacio con la lista.
- Al abrirlo muestra la lista fija de modelos y **Update model catalog**.
- **Check connection** es un enlace de texto azul alineado a la derecha del
  subtítulo **API key**, no un botón de ancho completo.
- El resultado de la conexión aparece bajo la cabecera y el de actualizar el
  catálogo junto al botón correspondiente. Ambos desaparecen a los 5 segundos.
- No se añade selector de modelo.
- La estructura debe reutilizarse para futuros proveedores con API key.

Criterios de aceptación:
- DeepSeek empieza con el catálogo cerrado.
- La lista y la actualización aparecen juntas al desplegar.
- La interacción funciona con teclado y en un panel estrecho.

Validación prevista: pruebas de webview, DOM y render real en VS Code.

## B02 - Minimal Usage section

Objetivo y resultado observable: los proveedores con API key muestran una
sección **Available balance** minimalista, sin subtítulo adicional.

Alcance y comportamiento:
- La sección sólo aparece para proveedores con API key.
- **Available balance** es el título único de la sección.
- El saldo se expresa en dólares y usa el saldo USD de DeepSeek.
- La sección sigue el tema de VS Code y se adapta a anchos estrechos.
- La barra de scroll del webview queda oculta visualmente sin bloquear rueda,
  teclado o gestos de desplazamiento.

Exclusión aprobada:
- **Usage dashboard**, selector de periodo y gráfica de gasto diario se posponen
  hasta que exista una API oficial de usage.

Criterios de aceptación:
- DeepSeek es el único proveedor que muestra Usage en esta versión.
- Una respuesta sin moneda USD no se presenta como dólares.
- No hay scroll horizontal ni desbordamiento en anchos estrechos.

Validación prevista: pruebas de webview y render real en VS Code.

## B03 - Available balance and alerts

Objetivo y resultado observable: el usuario ve sus créditos en dólares, puede
sincronizarlos y configurar alertas de saldo bajo.

Alcance y comportamiento:
- Consultar `GET https://api.deepseek.com/user/balance` con Bearer token.
- Mostrar el `total_balance` de la entrada `USD`.
- **Update** muestra un icono de sincronización y actualiza el saldo.
- Sincronizar al abrir el panel y cuando **Update** sea pulsado.
- Mientras el panel esté visible, sincronizar cada 60 segundos.
- Detener el polling al ocultar o destruir el panel; evitar peticiones solapadas.
- **Balance alert** abre un panel con X de cierre, valor inicial 5.00 y un campo
  para indicar el límite en dólares.
- El panel explica que se notificará cuando el saldo baje del valor indicado y
  que ponerlo a 0 desactiva las alertas de saldo bajo.
- El panel termina pegado al botón de cambio, sin espacio vertical adicional.
- La alerta se dispara sólo al cruzar por primera vez por debajo del límite.
- Llegar a cero dispara una alerta separada y vuelve a habilitarse al recuperar
  saldo.
- Saldo bajo: color amarillo. Saldo cero: color rojo.
- El límite y el último estado notificado se conservan entre recargas.

Decisiones registradas:

<!-- md-question {"id":"Q01","block":"B03","status":"answered","decision":"Polling cada 60 segundos sólo con el panel visible; sincronizar también al abrir y al pulsar Update."} -->
### Q01 - Cuándo sincronizar automáticamente

- A. Al abrir el panel y con **Update**, sin polling.
- B. Sólo con **Update**.
- C. Polling periódico mientras el panel esté abierto.

Respuesta del usuario: polling periódico cada minuto, sólo cuando el panel esté
abierto; además sincronizar al abrir el panel y con Update.

Consecuencias: crear un temporizador cancelable, pausarlo con el panel oculto y
no iniciar otra petición mientras una sincronización siga en curso.

<!-- md-question {"id":"Q02","block":"B03","status":"answered","decision":"Notificar sólo al cruzar el umbral o llegar a cero; reactivar la alerta al recuperar saldo."} -->
### Q02 - Repetición de alertas

- A. Sólo al cruzar el umbral o llegar a cero.
- B. En cada sincronización que siga por debajo.
- C. Máximo una vez al día por estado.

Respuesta del usuario: A.

Consecuencias: persistir el último estado notificado para evitar notificaciones
repetidas y rearmar las alertas cuando el saldo vuelva por encima del límite.

Criterios de aceptación:
- La API key nunca se envía al webview ni se registra.
- El polling se cancela correctamente al ocultar el panel.
- Los estados normal, bajo y cero son visual y accesiblemente distintos.
- Una respuesta CNY sin USD muestra que el saldo en dólares no está disponible.

Validación prevista: transporte HTTP simulado, temporizadores, persistencia y
pruebas de webview.
