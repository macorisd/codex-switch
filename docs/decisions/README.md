# Project decisions

Read this index at the start of each task, then read the documents relevant to
its scope before planning, implementing or verifying it. Accepted decisions apply
to new work as well as fixes. This directory is shared project knowledge;
`.agents/skills/.local/md-method/context.md` is only a local work log.

## Topics

| Document | Read when |
| --- | --- |
| [Project and delivery](project.md) | Changing source, providers, credentials, versions, documentation, packaging or release automation. |

## Maintenance

- Record the rule, scope, reason where useful, and its user instruction or plan
  source. Distinguish approved intent from implementation observations.
- When the user asks to save or changes a standing decision, update its topic
  and this index in the same task. New cross-cutting plan decisions belong here
  once approved; plans retain their questions, answers and delivery history.
- Replace superseded rules rather than leaving contradictory live instructions.
  Link history when needed. Do not promote a one-off workaround into a rule.
- Skip unrelated topics; document any deliberately excluded scope. A task-specific
  exception does not repeal a standing rule. Clarify only unresolved conflicts.
- Current user instructions take precedence. These documents never grant secret
  access, destructive operations, publication or permissions beyond the task.
